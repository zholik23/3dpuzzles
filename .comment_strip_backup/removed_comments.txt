    5: // A note on what the search does and does not settle.
    6: //
    7: // The loop is greedy and monotone: at each step it takes the first piece that
    8: // has a free direction, and never reconsiders. Two consequences worth being
    9: // straight about.
   10: //
   11: //   * Success is a genuine witness. The order it returns is a real removal
   12: //     sequence under the model that was passed in - each step was checked
   13: //     against the pieces still present at that moment.
   14: //   * Failure is NOT a proof of non-assemblability in general. It says this
   15: //     greedy descent got stuck; a different choice earlier might not have. It
   16: //     also only covers MONOTONE sequences, where a piece goes straight out and
   17: //     never moves again, and only ONE piece at a time - a puzzle needing two
   18: //     sub-assemblies mated together is outside the model.
   19: //
   20: // So the log reports "no piece is removable" as a fact about this run, not as a
   21: // theorem about the puzzle.
   22: //
   23: // Separately, and worth knowing before reading any result: for AXIS-ALIGNED
   24: // boxes the translational model can never reach that failure. The piece with
   25: // the largest hi[x] cannot have a neighbour on its +X face, because such a
   26: // neighbour would need a larger hi[x] still. So at every step at least one
   27: // piece is free, and the greedy loop always completes. A non-assemblable answer
   28: // from stages 1-3 as they stand would mean a bug, not a hard puzzle. The
   29: // failure branch is exercised by AlwaysBlocking, and will start doing real work
   30: // when the swept-volume model replaces the placeholder.
   81: // Assembly is the removal sequence played backwards, each piece going in
   82: // the way it came out.
