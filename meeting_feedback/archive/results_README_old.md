# Results

Generated by `../irit/puz2x2x2_nopins.irt`. Regenerate with:

```
cd meeting_feedback/results
grep -v "^view(" ../irit/puz2x2x2_nopins.irt > _batch.irt
echo "exit();" >> _batch.irt
"/c/irit/irit/windowsVC2026/ntbin64/irit64.exe" _batch.irt
```

`view()` is stripped because it needs a display server, and `exit()` is appended
because the interpreter otherwise spins at EOF in batch mode.

## Files

| Pattern | What it is | Size |
|---|---|---|
| `tv2x2x2_<shape>_r<NNN>.itd` | the randomised trivariate **M∘R** | ~21 KB |
| `puz2x2x2_<shape>_r<NNN>.itd` | the eight deformed tiles, for viewing | ~6 MB |

`<shape>` is `a` (puz_vol.irt's deformed sphere) or `b` (flatter, thicker wall).
`<NNN>` is R × 1000, so `r020` is R = 0.20.

**The trivariates are the inputs to the analysis.** The tile files are for
opening in GuIrit to confirm the pieces look like a puzzle; the analyser does
its own division in the parameter domain so that interface normals come from M
rather than from a tessellation.

## Verified

- Script runs headless, exit code 0, all 16 files produced.
- Randomisation confirmed: 132 control-point lines differ between `r000` and
  `r020` in the first 400 lines.
- Boundary control points are **byte-identical** across R, which is the correct
  behaviour — `RandomizeInterior` moves only interior points, so the outer shape
  is preserved and only the interior of the map is warped.
- Trivariate is 13 × 8 × 4 control points, orders 4, 4, 2.
